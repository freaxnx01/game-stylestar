# Date-Modus spielbar machen — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Den Date-Modus verdrahten — Startscreen-Button, Date-Themenwahl, den Date-Ablauf im bestehenden Ankleide-Screen und die gemeinsame Szene.

**Architecture:** Ausschliesslich `index.html`. Die Regeln existieren bereits (`scoreDate`, `recordDateResult`, `switchCharacterState` in `game-rules.js`, `DATE_THEMES` aus `wardrobe.js`) und werden nicht verändert. Der Ankleide-Screen wird wiederverwendet und über ein State-Feld `mode` umgeschaltet, nicht kopiert.

**Tech Stack:** Buildless ES-Module im Browser, das `sc-`Template aus `support.js`, `node --test`.

**Spec:** [`docs/ai-notes/specs/2026-09-13-date-flow-design.md`](../specs/2026-09-13-date-flow-design.md)

## Global Constraints

- **Nur `index.html` wird geändert.** `git diff --name-only origin/main` darf am Ende keine andere Datei nennen. Die Regeln aus #2 und #6 sind fertig und getestet.
- **Kein neuer Unit-Test, aber `npm test` muss grün bleiben** (≥ 49 Tests). Der Deliverable ist Verdrahtung; die Regeln dahinter sind bereits abgedeckt. Verifiziert wird per Durchspielen im Browser — jede Task nennt die konkreten Schritte.
- **`npm test` ist `node --test` ohne Pfadargument.** Ein Verzeichnis anzuhängen bricht auf Node 24 mit `MODULE_NOT_FOUND` ab.
- **Der Einzelmodus darf sich nicht ändern.** Jede Task prüft ihn mit.
- **Platzhalter im Template brauchen immer einen Wert.** Jeder neue `{{ name }}` muss im Initial-Objekt von `renderVals` mit einem Default stehen, sonst bricht der erste Render vor dem Laden der Module.

- [ ] **Step 4: `dateNext()` ergänzen**

Neben `startDateRound()`:

```js
  // Schritt 1 sichert das Outfit des Mädchens und schaltet auf den Jungen.
  // Schritt 2 bewertet beide Looks am selben Thema und speichert das Ergebnis.
  dateNext() {
    const looks = { ...this.state.dateLooks, [this.state.char]: { ...this.state.worn } };
    if (this.state.char === 'girl') {
      this.setState({ dateLooks: looks, char: 'boy', ...this.R.switchCharacterState(this.W.CHARACTERS.boy) });
      return;
    }
    const W = this.W, t = W.DATE_THEMES[this.state.dateIdx];
    const sc = this.R.scoreDate(W.CHARACTERS.girl, W.CHARACTERS.boy, t, looks.girl, looks.boy);
    const likes = 60 + sc.pts * 34 + Math.floor(Math.random() * 20);
    const prog = this.R.recordDateResult(this.state.progress, t.id, sc.stars);
    this.save(prog);
    this.setState({ dateLooks: looks, screen: 'dateResult', progress: prog, dateResult: { ...sc, likes }, likesShown: 0 });
    this.startLikes(likes);
  }
```

- [ ] **Step 5: Den Likes-Zähler als Methode herauslösen**

`finish()` startet den Timer heute inline. Der Block ab `clearInterval(this.likesTimer);` bis zum Ende von `finish()` wandert in eine eigene Methode, die beide Modi aufrufen:

```js
  startLikes(likes) {
    clearInterval(this.likesTimer);
    this.likesTimer = setInterval(() => {
      this.setState(s => {
        const n = Math.min(likes, s.likesShown + 3);
        if (n >= likes) clearInterval(this.likesTimer);
        return { likesShown: n };
      });
    }, 28);
  }
```

In `finish()` bleibt an dieser Stelle nur noch `this.startLikes(likes);`.
